# Omni Code

**웹 기반 AI Agent / IDE** — Claude Code 상당, 자신의 머신에서 실행.

> 🌐 **다른 언어로 읽기:** [English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

한 문장으로 지시하면 AI가 나머지는 알아서: 파일 읽기쓰기, 코드 검색,
명령 실행, 이미지素材 생성 — 이 IDE 자체 조작까지. 지켜보기만 하면 끝.

> ⭐ **셀프 개선 —— Omni Code를 별개로 만드는 기능.**
> Omni Code는 **자기 자신의 소스 코드를 고칠 수 있다**. **셀프 개선 모드**로 바꿔

## 빠른 시작

### 1. 동작 환경

- **XAMPP(PHP 8.2 + Apache)**, `curl` / `json` / `mbstring` / `openssl`
  4개 확장만 —— composer 불필요, 빌드 불필요, bundler 불필요
- 아무 **Claude / OpenAI / Gemini / OpenRouter** API 키(기본 브라우저 localStorage에만 저장)

### 2. 설치

1. 이 폴더를 `D:/xampp/htdocs/app/OmniCode`에 복사(htdocs 아래 어디든 가능)
2. XAMPP 제어판에서 Apache 시작
3. 브라우저에서 `http://localhost/app/OmniCode/app/` 열기
4. 물으면 API 키 붙여넣기(우상단 열쇠 아이콘) —— **개발은 Claude 권장**

`npm install` 불필요. 빌드 불필요. 프론트는素 `<script>`, 백엔드는 제로 FW PHP.

### 3. 표시 언어

**설정** 패널 상단 언어 드롭다운에서 **English / 繁體中文 / 简体中文 / 日本語 / 한국어**
즉시 전환. 기본은 영어; 설정은 `data/config.json`에 저장, 첫 paint 전 적용(깜빡임 없음).

## 🚀 셀프 개선 —— 스스로 자라는 도구

> 다른 agent는 **당신의** 프로젝트를 만든다. Omni Code는 **Omni Code 자체**를 다시 만들 수 있다.

채팅 헤더의 **셀프 개선 버튼**(또는 `Ctrl+Shift+S`)을 누르면
작업 공간이 Omni Code 본체 소스로 전환. 이후 말로 하면 된다:

- "설정 패널이 별로야, 모델 패널처럼 다시 만들어줘"
- "새 대화상자에 일본어 번역 붙여줘"
- "터미널 출력 읽기에 race condition이 있어, 찾아줘"

뒤에서 일어나는 일:

1. **한정 작업 공간** —— Agent 파일 권한은 Omni Code 본체에 고정,
   프로젝트와 동일한 안전 경계로 동작.
2. **히스토리와 버전**(`data/selfimprove/state.json`) —— 완료마다 기록:
   제목·요약·변경 파일·semver 올림(`patch` 수정, `minor` 신기능,
   `major` 구성 변경). 모델이 기록을 잊으면 시스템이 자동 보충.
3. **로드맵** —— 이후 작업은 버전 항목으로(`v1.0.0: …`). "X를 roadmap에"라고 하면
   세션을 넘어 남고, 완료 시 `roadmapItem`으로 자동 체크.
4. **셀프 패널** —— 버튼으로 히스토리·계획 뷰어도 열림: 어떤 버전에서 뭐가 바뀌고
   어떤 대화가 낳았는지(원클릭으로 그 대화로 복귀).

이 README 다국어판도, 설정 패널 다시 만들기도, 5언어 사전 자체도 ——
전부 Omni Code가 Omni Code 안에서 이렇게 만들었다.

## 기본 개념

### 작업 공간 —— 유일한 파일 안전 경계

**작업 공간은 디스크상任意 폴더면 된다**, Omni Code 아래가 아니어도 됨. 전환 3가지:

1. 상단바 폴더 경로 클릭 → 탐색 or 경로 직접 붙여넣기
2. 터미널에서 작업 공간 밖에 `cd` → "여기로 전환" 버튼 등장
3. 사이드바 "설정 → 작업 공간 변경"

> **단일 프로젝트 폴더를 고르세요. `htdocs`나 드라이브 전체는 NG.**
> 작업 공간은 검색과 파일 트리의 범위: 수십만 파일目录를 고르면
> 전체 검색이 타임아웃으로 부분 결과만 옴(명시는 되지만体验 나쁨).
> 기본은 Omni Code 자체 폴더 ——試し場으로どうぞ.

**왜 작업 공간이 필요한가?** Omni Code 유일한 파일 안전 경계이므로.
Agent는 작업 공간 안에 100% 권한(생성／삭제／변경／이동),
밖 경로는 백엔드가 거부. 프로젝트 바꾸기 = 작업 공간 바꾸기, 한 번에 1범위.

### 시작

오른쪽 입력란에 한 마디:

- "이 프로젝트 구성 좀 봐줘"
- "app/js 로그인 검증에 경계 버그가 있어, 고치고 테스트도 추가해줘"

`/`는 슬래시 명령(`/doctor` 헬스체크, `/compact` 압축,
`/forget <이름>` 기억 삭제…). `@`로 파일 언급, `Shift+Tab`으로 권한 모드 순환.

### Mode —— 실행 전 얼마나 물을지

| 모드 | 의미 |
|---|---|
| 📋 계획 | 조사만: 읽기·검색 가능, 쓰기·명령 불가 |
| ● 수동 | 쓰기·명령 실행 전 확인(가장 안전한 일상 모드) |
| ✏️ 자동 편집 | 파일 생성／변경／삭제 확인 불필요; 명령은 확인 |
| 🚀 전체 자동 | 100%: 전 파일 작업·명령·네트워크 자동 승인 |

안전 경계는 항상 유효: 작업 공간 내부만, 로컬 연결만.

### Effort —— 추론 강도

Claude Code와 동명(`off` → `max`). 추론은 token을 쓰지만 최종 답변에 안 나옴.
모델별 상한은 자동 존중, 무리 안 시킴.

## 안전

- 서비스는 `127.0.0.1`만 수신, 나머지는 403
- Agent 파일 권한은 선택 작업 공간에 엄격 한정, 탈출은 백엔드가 거부
- API 중계는 도메인 화이트리스트 —— 오픈 프록시 안 됨
- API 키는 기본 브라우저 localStorage에만

**공개망에 노출 금지.** 로컬 파일 완전 권한을 전제로 설계됨.
